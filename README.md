# llama2.c on an FPGA: a whole language model on one chip

We run Karpathy's [llama2.c](https://github.com/karpathy/llama2.c) TinyStories model (stories260K)
entirely inside an Opal Kelly XEM7310 FPGA (Xilinx Artix-7 xc7a75t). The weights, the KV cache,
all 5 transformer layers, the classifier, argmax and the generate loop all live on the chip. The
laptop sends a prompt over USB and gets the generated story back.

**Result: 13,333 tokens/s measured on the chip, bit-exact against our golden model.** That is
1.62x a MacBook M3 Pro running llama2.c compiled with `clang -O3`.

| stories260K, 256 positions | tokens/s |
|---|---|
| **XEM7310 FPGA, this design (133 MHz)** | **13,333** |
| Same design on a smaller Spartan-7 board (our first version) | 8,981 |
| MacBook M3 Pro, llama2.c `clang -O3` | 8,225 |
| MacBook M3 Pro, llama2.c `-O3 -ffast-math -mcpu=native` | 15,937 |

Streaming stories continuously over USB, including all host overhead, gives 9,053 new tokens/s.
All 8 test prompts produce exactly the tokens our C++ golden model predicts, on the real board.

## What's in the repo

Everything for the submission is in [`xem7310/`](xem7310/). Its [README](xem7310/README.md)
has the full details, build steps and endpoint map.

| what | where |
|---|---|
| **Bitstream** (tested on the board) | `xem7310/bitstreams/llama_xem7310_top.bit`, with its timing and utilization reports |
| **Model weights** (FP4, as the on-chip ROM image) | `xem7310/fp4/model_rom.h`, made from llama2.c's `stories260K.bin` by `llama/fp4/convert.py` |
| **Tokenizer** | `xem7310/fp4/tok512.bin` (llama2.c's stories260K tokenizer) |
| **Accelerator source** (C++ for Vitis HLS; it is also the bit-exact golden model) | `xem7310/fp4/llama_fp4.cpp`, `llama_fp4.h` |
| **Verilog / SystemVerilog** | `xem7310/rtl/llama_xem7310_top.sv` (board top: USB, clocks, FIFOs), `xem7310/rtl/fp_cmd_proc.sv` (USB command processor), `xem7310/rtl/tb_fp_cmd_proc.sv` (testbench) |
| **Constraints and build scripts** | `xem7310/constraints/llama_xem7310.xdc`, `xem7310/fp4/run_hls.tcl`, `xem7310/build.tcl` |
| **Host program** | `xem7310/host/fp4_ok_host.py` (run, check, stream) |
| **Golden tokens** the board must reproduce | `xem7310/fp4/golden/` |

The accelerator's own Verilog is generated by Vitis HLS from `llama_fp4.cpp` during the build
(`run_hls.tcl`) and is compiled into the bitstream. `llama/` holds the earlier Spartan-7 version
of the same accelerator, which this port grew out of.

## How it works

- **Weights in FP4.** Each weight is a 4-bit float (E2M1) in blocks of 16 that share an 8-bit
  scale. The whole model fits in the FPGA's block RAM, so no external memory is involved.
- **Exact integer math.** Activations are quantized to int8 with power-of-two scales. Each
  matrix multiply is exact integer arithmetic, 128 FP4 multiply-adds per clock. Every float step
  is a single IEEE operation, so the FPGA matches the C++ model bit for bit.
- **Attention on chip.** An int8 KV cache holds 256 positions. All 8 heads are scored in one pass
  over the cache, and softmax uses a lookup table.
- **USB link.** The host sends one batch of commands per run over Opal Kelly FrontPanel. An
  on-chip command processor writes the prompt, starts the model, waits for it and returns every
  token, so the host never polls the model over USB.
- **Quality.** Against fp32 llama2.c, the FPGA picks the same next token 85.3% of the time
  (teacher-forced on llama2.c's own outputs).

## Run it

You need the XEM7310 on USB and the Opal Kelly FrontPanel Python binding (`ok`). Vivado is not
needed to run the tested bitstream.

```bash
export DYLD_LIBRARY_PATH="$HOME/cs1410_lab/lib/macOS"   # where the FrontPanel binding lives
cd xem7310
python3 host/fp4_ok_host.py --bit bitstreams/llama_xem7310_top.bit check   # program + verify 8 prompts
python3 host/fp4_ok_host.py run -i "Once upon a time" -n 256                # one story, prints tok/s
python3 host/fp4_ok_host.py stream                                          # endless stories, Ctrl-C to stop
```

Rebuilding the bitstream needs Vitis HLS and Vivado 2022.2; see
[`xem7310/README.md`](xem7310/README.md#rebuild-needs-ssh-cs1410vnc).
